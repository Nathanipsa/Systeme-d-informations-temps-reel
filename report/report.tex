This report details the exhaustive schedulability analysis and non-preemptive schedule formulation for a specific periodic task set. The core objective is to map out a deterministic execution flow where no temporal constraints are violated, whilst minimizing the cumulative waiting time of the spawned jobs.\\

Furthermore, this analysis investigates the system's flexibility by testing a relaxed scenario where a specific task ($\tau_5$) is permitted to miss its deadline, observing how this impacts the overall optimization matrix. A Branch and Bound algorithmic approach written in C was utilized to ensure a rigorous traversal of the solution space.

\chapter{SYSTEM MODELING AND WCET EXTRACTION}

\section{WCET Evaluation for $\tau_1$}
Task $\tau_{1}$ involves calculating the product of large randomly generated numbers. To prevent too short execution times due to C compiler optimisation, the number is given as type \rond[green]{versatile long long int}. To acquire an accurate statistical representation of its execution, 1000 compilations and runtime evaluations were simulated. \\

The empirical tests revealed an execution profile characterized by the following metrics:
\begin{itemize}
    \item \textbf{Q1:} 0.53 ns
    \item \textbf{Median (Q2):} 0.54 ns
    \item \textbf{Q3:} 0.56 ns
    \item \textbf{WCET ($C_1$):} $\approx 1.3$ ns
\end{itemize}

\section{Data Scaling Strategy}
To implement a precise programmatic scheduler at the job level, computing times strictly as integers is preferred to prevent floating-point inaccuracies and buffer anomalies. Because the observed WCET for $\tau_1$ was $1.3$, a scaling factor was universally applied.\\

All task properties (Computation Time $C_i$ and Period $T_i$) from the initial dataset were \rond[green]{multiplied by a factor of 10}. This allows $C_1 = 1.3$ to be safely represented as $13$ inside the algorithmic domain without distorting the utilization factor.

\chapter{SCHEDULABILITY AND OPTIMIZATION}

\section{Processor Utilization and Hyperperiod}
Before attempting to find a schedule, the theoretical schedulability must be verified. The total processor utilization $U$ is given by \rond{$\displaystyle U = \sum_{i=1}^{n} \frac{C_i}{T_i}$}.

\[
U = \frac{13}{100} + \frac{30}{100} + \frac{20}{200} + \frac{20}{200} + \frac{20}{400} + \frac{20}{400} + \frac{30}{800} = 0.7675
\]

Since \rond{$U = 0.7675 \le 1$}, the task set is theoretically schedulable.

\begin{proposition}{The Hyperperiod Assumption}
    To prove permanent schedulability for a periodic task set without simulating infinite time, the schedule only needs to be verified across one \textbf{Hyperperiod}. The hyperperiod is the Least Common Multiple (LCM) of all task periods.

    \[
    H = \text{LCM}(100, 100, 200, 200, 400, 400, 800) = 800
    \]

    \tcblower

    Over one hyperperiod, exactly $29$ distinct jobs are spawned. If a valid, non-overlapping sequence exists for these 29 jobs within $t \in [0, 800]$, the system is indefinitely schedulable.

\end{proposition}

\section{Algorithmic Complexity}

The scheduler is built on a \textbf{Branch and Bound (B\&B)} search tree. 
Let $N$ be the total number of jobs within the hyperperiod ($N = 29$). The problem of sequencing $N$ non-preemptive jobs optimally is NP-Hard.

The worst-case computational complexity is inherently bounded by the permutations of jobs, leading to \rond[red]{$\mathcal{O}(N!)$} complexity. However, the B\&B algorithm aggressively prunes the search space by bounding:

\begin{enumerate}
    \item Any branch where the current accumulated wait time exceeds the best-known minimum is instantly pruned.
    \item Any branch where the temporal constraints $start\_time + C_i > deadline$ are violated is discarded.
\end{enumerate}

\section{Minimizing Wait Time and Maximizing Idle Time}

The instruction set mandates finding a schedule that minimizes total waiting time, which implies that total processor idle time is maximized. 

\textbf{Verification of this relationship:}

The absolute sum of execution times over the hyperperiod is constant ($\sum C_i \times \frac{H}{T_i}$). Consequently, the absolute sum of idle time ($H - \text{Active Time}$) is structurally fixed at $800 - 614 = 186$. However, minimizing the waiting delay forces the scheduler to execute jobs immediately upon their release. This consolidation eliminates micro-fragmentation between jobs, thereby grouping the scattered processor idle ticks into the \textit{maximum contiguous idle blocks} possible.

\section{Scenario 2: Relaxed Constraints ($\tau_5$ Delay)}

In the subsequent run, the scheduling strictness is relaxed allowing $\tau_5$ to miss a deadline to potentially decrease the cumulative waiting times of higher-frequency tasks. 

When the pruning guardrail for $\tau_5$'s deadline ($D_5$) is deactivated:

\begin{itemize}
    \item The algorithm explores previously forbidden permutations where $\tau_5$ yields the processor.
    \item Because $\tau_5$ has a massive period (400) compared to $\tau_1$ (100), delaying $\tau_5$ past its deadline removes significant wait bottlenecks for the subsequent immediate releases of $\tau_1$ and $\tau_2$.
    \item \textbf{Result:} Even though $\tau_5$ can misses its deadline, the total wait time for the remaining tasks doesn't move at all. This confirms that the optimal schedule is already achieved under strict constraints.
\end{itemize}

\chapter*{CONCLUSION}
\addcontentsline{toc}{chapter}{CONCLUSION}

This analysis successfully demonstrates that the provided task set is schedulable under non-preemptive constraints. Through data scaling, floating-point ambiguity was bypassed, enabling a robust Branch and Bound traversal. By mapping out a full hyperperiod ($H=800$), the scheduler validated that a combination minimizing wait times guarantees maximum contiguous processor idle time. However, allowing $\tau_5$ to miss its deadline did not yield any improvement in the total wait time, confirming that the optimal schedule is already achieved under strict constraints.
